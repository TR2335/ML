**一条主线**：每一步进化都由上一步暴露的缺陷驱动——小样本看不出来的问题，在变大、变真之后依次显形。

## 2. 六条方法学进化线

| 维度 | 进化路径 | 每次换血的动因 |
| --- | --- | --- |
| **模型** | 手写逻辑回归（P0）→ sklearn 管线：中位数填补→标准化→L2，C∈{0.01,0.1,1} 按时间 CV AUPRC 选取（P6）→ LightGBM opt-in 挑战者：单调约束+限 trials optuna（P7） | 手写版无预处理契约与 CV；单一模型无挑战者就没有"更好的存在证明" |
| **校准** | 无（P0–P5）→ Platt（P6）→ isotonic + 低分辨率自动回退（P7） | 无校准的概率不可直接用于阈值决策；Platt 参数形式在非线性校准段有偏 |
| **验证** | 无 → 滚动时间切分 + bootstrap 95% CI，时间戳不跨折（P5）→ golden 数据集钉住离在线一致（P6）→ **患者级切分防泄漏**（本轮，P9 前置） | 随机切分必然时间泄漏；离在线可以悄悄漂移；同患者多行跨折是更隐蔽的泄漏 |
| **门禁** | 无 → bootstrap AUPRC 下界 ≥ NEWS2 + ECE<0.05（P6）→ + 对 LACE（P8）→ + 亚组灵敏度差 ≤10% + 逐院区 AUPRC ≥ 基线 + 决策曲线平均增益 ≥0（P7） | 每条新规则都对应一种"总指标好看但局部翻车"的失效模式 |
| **基线** | 无 → NEWS2（P5）→ LACE（P8） | 模型必须赢过临床在用的打分工具才有存在价值 |
| **漂移监控** | 无 → 训练写 `drift_reference`、PSI>0.2 告警、门禁内再校准（P7）→ **+ KS 效应量双检**（本轮） | 上线后分布会动；单一 PSI 对分箱敏感 |

配套冻结项（进化中确立、不再动）：特征顺序 `feature_order` 写入工件并在加载时校验；阈值走灵敏度阶梯（手算基准 {0.10, 0.20, 0.30}）；两目标独立 artifact、独立阈值、独立审批。

## 3. 为什么不用：弃用与不采用决策

### 3.1 模型与训练

| 候选 | 结论 | 原因 | 替代 |
| --- | --- | --- | --- |
| 深度学习（MLP/时序网络） | **不适用** | 表格型七元组特征 + 万级样本，深度模型收益低；serving 纯标准库无法承载推理依赖；黑盒在医疗审评下举证成本高 | 逻辑回归打底 + LightGBM 挑战者，真实数据到位后按时间外验证/校准/净获益择优 |
| XGBoost / CatBoost | **不采用** | LightGBM 已覆盖梯度提升；纯 Python 树打分（路径行走）是手写维护面，多一个框架就多一份校验与工件校验负担 | LightGBM（`--algorithm lightgbm`，opt-in） |
| 在线/增量学习 | **不适用** | 30 天再入院标签有成熟窗口；模型发布要过门禁与审批，训练必须是可复现的批式过程 | 定期重训 + 门禁内再校准（`recalibrate.py`） |
| 大范围超参搜索 | **不采用** | 可复现性与时间预算优先；万级样本上调参收益远小于数据质量 | LR：C 网格 CV；LightGBM：optuna TPE 限 trials |
| SMOTE / 合成过采样 | **不采用** | `class_weight=balanced` 已修正先验；合成少数类会扭曲概率分布，直接伤害校准（Platt/isotonic 都会拟合到假形状） | 类别权重 + 校准层，代价靠 AUPRC/PPV 口径管理 |

### 3.2 验证与评估

| 候选 | 结论 | 原因 | 替代 |
| --- | --- | --- | --- |
| 随机 K 折 / 行级切分 | **弃用** | 双重泄漏：未来时间进训练集；同一患者的多条 landmark 行跨折 | 滚动时间切分（P5，时间戳不跨折）→ 患者级切分（本轮） |
| AUROC 作主门禁指标 | **不采用** | 阳性率个位数时 AUROC 乐观且与阈值无关，不反映告警质量 | AUPRC 为主 + ECE + 每日告警量/决策曲线 |
| 以 p 值判漂移显著性 | **不采用** | 2.5 万样本下任何微小偏移都会 p<0.001，告警必然疲劳 | 效应量阈值：PSI>0.2、KS>0.1（本轮） |
| 逐小时 landmark 全量网格 | **本轮弃用** | 2.5 万遭遇 × 96 = 240 万行，CSV 逼近 GB 级、bootstrap 不可行 | 6h 网格 ≈ 40 万行（horizon=24h > cadence，捕捉能力不损失） |
| 全量行 bootstrap | **本轮弃用** | O(n_bootstrap × n_rows) 纯 Python，40 万行 × 1000 次 = 数亿次操作 | replicate 子采样 ≤2 万行 + n=500，报告卡注明 `replicate_subsample` |

### 3.3 系统与工程

| 候选 | 结论 | 原因 | 替代 |
| --- | --- | --- | --- |
| sklearn/numpy/scipy/lightgbm/optuna 进 `app/` | **永不采用** | serving 依赖树、部署体积与安全面失控（P5 起硬约束，每轮验证） | 训练/评估侧（`[train]` 依赖）自由使用；打分纯 Python（逻辑回归点积 / 树路径行走） |
| 校验、权限、事务、阈值、审计、临床处置用 ML | **不适用** | 这些环节要的是确定性与可审计，统计模型反而引入不可复核性 | 规则系统承担；ML 只做有历史信号的预测与排序 |
| 两目标共用一个输出 | **不采用** | 索引时点、标签窗口、患病率、误报代价、干预流程全不同，共用会互相污染阈值与审批 | 两个独立 artifact + 各自阈值/版本/验证报告 |
| 演示 18 患者数据当验证依据 | **不适用** | 样本量下指标无置信度、泄漏与漂移问题不显形 | 本轮 2–3 万规模演练作为 P9 前的方法学彩排 |
| 缺分组键/缺参考样本时静默降级 | **不采用** | 静默降级 = 假阴性通过，是最危险的失败模式 | 缺分组键响亮报错；缺 KS 参考样本注明跳过不判失败 |

## 4. 经历过的问题（现象 → 根因 → 处置）

### 4.1 方法学问题

| # | 问题 | 根因 | 处置（裁定） |
| --- | --- | --- | --- |
| 1 | 滚动切分把**同一时间戳**的行分进训练与测试两侧，时间序保证失效 | 行级排序在边界处切断同戳组 | 时间戳分组切割、整组进块——「每个时间戳不跨折」 |
| 2 | **同患者多条 landmark 行跨折泄漏**（本轮识别，P9 前必修） | 一切按行分组，患者身份未参与切分 | `patient_rolling_time_split`：按患者首时点分块 + 返回前断言患者交集为空；缺分组键响亮报错 |
| 3 | 阈值阶梯**手算基准算术错误**：计划原稿写 0.25/0.35，实际推导是 0.10/0.20/0.30 | 手算未复核 | 修正基准并立规：阈值手算必须二次复核算术 |
| 4 | 种子预置的 readmission 分数**永久挡触发写入** | lifespan 种子把 `as_of` 钉在首个出院事件，后续触发被吞 | P8 移除 lifespan 种子——「种子不得永久挡触发写入」 |
| 5 | demo 数据上 isotonic 校准段**只有 2 个分辨率档**，校准退化 | in-sample PAV 分箱过少 | R-P7-5a：低分辨率自动回退 Platt 并写 `fallback_reason=isotonic_resolution`；真实数据块数充足自动走 isotonic |
| 6 | 恒分输入的 AUPRC 经 (score,label) 元组**平局判定得 1.0**（P5 遗留怪癖） | `binary_metrics` 平局排序口径 | 已登记 deferred（修复需同步门禁 fixture），刻意未在热路径上顺手改 |
| 7 | CV 中**单类测试折** auprc 计 0 拉低选择信号 | 折内无阳性 | 单类折跳过不参与比较 |
| 8 | PSI 计算中**空箱被 ε=1e-6 级别的 epsilon 对数放大** | 加性平滑取值过小 | 业界惯例 0.005 对称平滑 |
| 9 | LightGBM 树工件可被构造成**环/子索引越界/内部负索引**，打分器会挂死或错走 | 纯 Python 路径行走无框架保护 | 载入期严格校验，任一违规响亮拒绝 |
| 10 | 门禁规则缺输入时可能**静默放行** | 「查不到就当过了」 | 「不可用即跳过并注明」：规则 `skipped` 不判失败，但必须进 eval.json `rules` 留痕 |

### 4.3 诚实边界

- 已知未修：24 项终审 deferred minors 清单在 `docs/superpowers/STATUS.md`（含 #6 的 AUPRC 平局怪癖、isotonic Brier 不劣化无断言等）；
- 合成数据下的一切指标只证明**管线与方法学成立**，不证明模型真实性能——真实性能要等 P9 真实数据；
- 当前最优校准/判别结论均可能被真实数据推翻，这正是流程里保留"门禁 + 挑战者 + 终审"的原因。

## 5. 本轮：按真实项目标准的规模优化（2–3 万出院/入院）

假装拥有 2–3 万条出院/入院记录，按真实项目标准补齐最后的方法学短板（设计已入档：`docs/superpowers/specs/2026-10-12-medintel-real-scale-optimization-design.md`）：

1. **规模化合成队列**：25,000 遭遇 / 18 个月 / 3 院区 / 再入院率 12% / 恶化率 4% / 真实缺失画像；
2. **患者级切分防泄漏**（§4.1 #2 的正式修复）；
3. **自动模型报告卡**：10 固定章节，只许复用既有指标函数，防口径漂移；
4. **漂移 KS 双检**（§3.2 的 p 值裁定落地）；
5. **端到端规模演练**：七步编排 + 时间预算 + 泄漏断言 + 门禁全过，产出机读报告。

实施顺序 T1–T7 见 spec §9；弃用理由见本文 §3，历史问题见 §4。

## 6. 沉淀下来的进化方法论

1. **缺陷驱动**：每次换血都来自上一阶段暴露的具体失效，不追新方法（§1 主线）；
2. **弃用要有理由、记录在案**：§3 每一行都能追到裁定（Plan Ruling）或教训；
3. **失败要响亮**：缺数据/缺参考/缺分组键，要么报错要么注明跳过，永远不静默通过；
4. **不变量写进代码**：时间戳不跨折、患者不跨折、golden 一致、门禁留痕——不靠自觉；
5. **双链路互不干扰**：演示链路（18 患者、golden、全量测试）与规模链路并行，动谁都不伤另一条；
6. **新上下文终审 + 唯一修复轮**：防止实现者自批（§4.2 #13）。
