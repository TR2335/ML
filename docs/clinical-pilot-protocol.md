# 临床 P0 试点协议模板

这份模板用于在医院真实数据到位后完成临床目标确认、静默运行和上线决策。它不能替代医院伦理、质量或医疗器械审批。

## 目标与标签

| 目标 | 必须由临床团队签字确认的标签 |
| --- | --- |
| `deterioration_24h` | 索引时间后 24 小时内的恶化事件集合，例如 ICU 转入、无创/有创通气、升压药、心肺复苏或院内死亡；必须确定事件编码、时间窗和排除规则 |
| `readmission_30d` | 出院后 30 个自然日内的非计划再入院；必须确定跨院区匹配、计划性再入院、转院和死亡的处理规则 |

两个目标不能使用同一组合标签。标签版本、纳入/排除条件、缺失处理和时间窗必须进入模型版本审批记录。

## 数据和验证顺序

1. 建立脱敏患者主索引、就诊主索引和跨系统事件血缘。
2. 按时间切分训练、验证和测试数据；同一患者不能跨集合泄漏。
3. 在独立时间段和至少一个外部院区验证 AUROC、AUPRC、Brier、校准、灵敏度、特异度和决策曲线。
4. 按年龄、性别、院区、科室、设备、语言和其他医院认定的重点人群输出亚组报告。
5. 使用 `scripts/evaluate_model.py` 生成可归档的指标报告，临床团队确认阈值和告警负荷。

## 静默运行

至少连续运行一个预先约定的观察周期。模型产生分数但不向临床人员展示决策提示，记录：

- 每日覆盖率、缺失率和事件延迟；
- 各目标的告警数量、分层分布和重复告警率；
- 真实标签发生率、漏报和误报；
- 不同科室和亚组的性能差异；
- 服务延迟、事件积压、失败重试和模型版本。

## 上线门槛

上线前必须由临床负责人、质量负责人、信息安全负责人和模型负责人共同签字确认：

- 标签、阈值、告警升级和人工处置 SOP 已冻结；
- 两个目标的模型卡、验证报告和风险分析已归档；
- 误报不会造成不可接受的告警疲劳，漏报有人工安全网；
- OIDC、PostgreSQL、备份恢复、审计、监控和回滚演练通过；
- 任何模型异常都能切换到人工或规则版流程；
- 临床人员完成培训并通过用户验收测试。

任何一项未完成时保持静默运行或停止发布，不把演示模型用于诊疗决策。
